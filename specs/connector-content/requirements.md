# CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R001` | **Default content.** `pyproject.toml` declares `craft-suite-api` as the single `scion_sdk.connector` entry point. The server lists the packaged `skill://` and `ontology://` resources and the packaged prompts with no `content=` argument. Proving test: `tests/test_default_content_surfaces.py`. Caller chain: the `craft-suite-mcp` console script (pyproject.toml) loads the `scion_sdk.connector` entry point `craft_suite_api:connector` -> craft_suite_api/__init__.py::connector (a Connector with no content= argument) -> the SDK default content registration serves skill://, ontology:// and prompts. Shape: tests build the server from craft_suite_api and list resources and prompts over the packaged craft_suite_api/skills, craft_suite_api/ontology and craft_suite_api/prompts directories. | `resources/list` includes `skill://` and `ontology://`; `prompts/list` includes each packaged prompt. Test: `tests/test_default_content_surfaces.py::test_default_content_surfaces`. |
| `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R002` | **Replace the stub ontology with the core pack classes.** Subsystem: content tier, ontology. Rewrite `craft_suite_api/ontology/artcraft.ttl`. Delete the stub class `:ArtcraftResource` and its properties. Declare three classes: `:App` as a subclass of `:Application`, `:AppTool` as a subclass of `:Tool`, and `:UseCase` as a subclass of `:Task`. Declare the properties `:ofApp` (from `:AppTool` to `:App`), `:forApp` (from `:UseCase` to `:App`), `:usesToolName` (from `:UseCase` to a string), `:appNamespace` and `:appVersion`. The pack never declares `owl:imports` of the engine ontology. Every class reaches a core class through `rdfs:subClassOf`. The pack never redeclares a core class. Refusals come from the engine at import: `ONTOLOGY_PACK_IMPORTS_CORE`, `ONTOLOGY_ORPHAN` and `ONTOLOGY_CORE_CONFLICT`. Caller chain: the packaged `ontology/*.ttl` listing of `build_server` (`SCION-CONNECTOR-CONTROL-R073`) → `ConnectorPack.Import` (`MEDULLA-TYPED-PACKS-R105`). Shape: one Turtle file and the test; the test parses the file and walks the `rdfs:subClassOf` edges to the names `:Application`, `:Tool` and `:Task` in the core modules. Depends on: `MEDULLA-TYPED-PACKS-R071.2`, `MEDULLA-TYPED-PACKS-R102.3`, `MEDULLA-TYPED-PACKS-R105`. | `tests/test_artcraft_ontology.py::test_pack_classes_extend_core_and_import_nothing` (planned in `test-spec.md`). Three classes exist. Each reaches a core class. The file holds no `owl:imports` line and no stub class. |
| `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R003` | **Generate one ontology file per app.** Subsystem: content tier, ontology. For each app the generator writes `craft_suite_api/ontology/artcraft-<app>.ttl`. The file holds an `owl:Ontology` node with the IRI `http://knuckles.team/kg/artcraft/<app>`, one `:App` individual with `:appNamespace` and `:appVersion`, the app's domain classes, and one `:UseCase` individual for each functionality of `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R005`. Each domain class comes from `content/apps/<app>.yml` and names one parent class. The parent must be one of `:CreativeWork`, `:Document`, `:Artifact`, `:App` or `:AppTool`. The file may `owl:imports` the sibling `http://knuckles.team/kg/artcraft` only, and never the engine ontology. Refusals: `CONTENT_PARENT_UNKNOWN` when a class names another parent. Knobs: none. Caller chain: `scripts/generate_app_content.py` → `render_ontology` in `craft_suite_api/content_gen/ontology.py` → the file; the server lists the file as an `ontology://` resource. Shape: `render_ontology` is a pure function from the app source and the snapshot to Turtle text. Reuse `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R001` for listing. Depends on: `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R002`, `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R006`. | `tests/test_app_ontology_render.py::test_each_app_file_extends_core_and_unknown_parent_refuses` (planned in `test-spec.md`). Eleven files are produced. Every class reaches a core class. A class with another parent fails with `CONTENT_PARENT_UNKNOWN`. |
| `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R004` | **Generate one skill per app.** Subsystem: content tier, skills. For each app the generator writes `craft_suite_api/skills/<app>/SKILL.md`. The front matter holds `name` and `description`. The body holds: when to use the app; the activation step (`registry_activate` with the namespace); a tool table generated from the snapshot with each tool name as `<app>_<tool>` and its first description sentence; and the functionality list that links to the prompt names. The server lists each file as a `skill://` resource. The skill `artcraft-starter` stays for Tier 1. Refusal: `CONTENT_SKILL_TOOL_UNKNOWN` when an authored section names a tool that the snapshot lacks. Caller chain: `scripts/generate_app_content.py` → `render_skill` in `craft_suite_api/content_gen/skill.py`; the listing runs through `build_server`. Shape: a pure function from the app source and the snapshot to Markdown. Depends on: `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R006`. | `tests/test_app_skill_render.py::test_skill_lists_every_snapshot_tool_and_refuses_unknown_tool` (planned in `test-spec.md`). Each skill table holds every snapshot tool once. A tool name missing from the snapshot fails with `CONTENT_SKILL_TOOL_UNKNOWN`. |
| `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R005` | **Generate prompt packs per functionality.** Subsystem: content tier, prompts. Each app source file lists functionalities. A functionality has a `name`, a `description`, an ordered `tools` list and `steps`. For each one the generator writes `craft_suite_api/prompts/<app>-<functionality>.json` with the same keys as `artcraft_specialist.json`. The prompt tells the model to activate the namespace first and names only tools that the snapshot lists. It sets `requires_namespace` to the app name. Each functionality is also one `:UseCase` individual in the app ontology (`CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R003`). Refusal: `CONTENT_PROMPT_TOOL_UNKNOWN` for a tool absent from the snapshot. A tool in the snapshot with no functionality is listed in the generator report as unassigned. It is not a failure, because the skill table still lists it. Caller chain: `scripts/generate_app_content.py` → `render_prompts` in `craft_suite_api/content_gen/prompts.py`; the server lists each file through the `scion_sdk.prompt_providers` entry point. Shape: a pure function to JSON text; reuse the key set of the existing prompt file. Depends on: `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R006`. | `tests/test_app_prompt_render.py::test_prompt_per_functionality_names_only_snapshot_tools` (planned in `test-spec.md`). One prompt exists for each functionality. Each prompt holds `requires_namespace`. An unknown tool fails with `CONTENT_PROMPT_TOOL_UNKNOWN`. |
| `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R006` | **Content generator and tool snapshots.** Subsystem: content tier, generator. Add `scripts/generate_app_content.py` with the modes `--check`, `--write` and `--refresh`. `--refresh` starts `<app>-cli mcp`, reads `tools/list` and the server version, and writes `content/snapshots/<app>.tools.json`. It sorts tools by name and keeps each name, description and input schema. It starts a real CLI, so it runs on a host that has one. `--write` renders the ontology, skill and prompts from `content/apps/<app>.yml` and the snapshot. `--check` renders in memory and compares bytes. The tool names in a snapshot are the upstream names. The generator adds the namespace prefix when it writes content. Knobs: `refresh_timeout_s` 30 (range 5..300). Refusal: `CONTENT_SNAPSHOT_MISSING` when an app has a source file and no snapshot. Caller chain: operator or CI runs the script → `main` → the three render functions of `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R003` to `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R005`. Shape: `scripts/generate_app_content.py` and the package `craft_suite_api/content_gen/`; reuse the SDK client for `--refresh`. Depends on: `CONN-CRAFT-SUITE-API-APPS-R002`. | `tests/test_generate_app_content.py::test_write_is_deterministic_and_missing_snapshot_refuses` (planned in `test-spec.md`). Two `--write` runs give identical bytes. An app without a snapshot fails with `CONTENT_SNAPSHOT_MISSING`. |
| `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R007` | **Drift gate for generated content.** Subsystem: content tier, drift. The offline gate runs `generate_app_content.py --check` in CI. It fails when any committed ontology, skill or prompt differs from the render of its sources, with the finding `CONTENT_DRIFT` that names the file. This gate needs no app CLI. The live gate runs `--refresh` into a temporary directory on a host with the CLIs and compares each fresh tool fingerprint with the committed snapshot. The fingerprint is the SDK `compatibility_fingerprint` of each tool (`SCION-CONNECTOR-CONTROL-R914.11`). A difference fails with `CONTENT_SNAPSHOT_STALE` and lists the added, removed and changed tool names. The live gate runs after each app update, together with `craft-suite-probe` (`CONN-CRAFT-SUITE-API-APPS-R003`). Caller chain: pre-commit and CI call the offline gate; the host job calls the live gate. Shape: a `--live` flag on the script and one pre-commit hook entry. Depends on: `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R006`. | `tests/test_content_drift_gate.py::test_offline_gate_flags_edited_file_and_live_gate_flags_stale_snapshot` (planned in `test-spec.md`). An edited generated file fails with `CONTENT_DRIFT`. A fixture CLI with one changed schema fails the live gate with `CONTENT_SNAPSHOT_STALE`. |
| `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R008` | **Hot-path proof: the packaged content imports cleanly and answers a class query.** Subsystem: content tier, onboarding. Entry: the served `ConnectorPack.Import` of the pack built from the packaged content. The pack holds the core ontology file, eleven app ontology files, twelve skills and the prompts. The import reports no `ONTOLOGY_ORPHAN` and no `ONTOLOGY_PACK_IMPORTS_CORE`. A class query over `:Application` returns `:App`. A query over `:Task` returns `:UseCase`. Caller chain: `build_content_pack` of the `scion-sdk` package (module `scion_sdk.artifacts.pack`) → the served import (`MEDULLA-TYPED-PACKS-R105`) → a served `UnifiedQuery`. Shape: one test module with a loopback engine fixture; no production code. Depends on: `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R002`, `CONN-CRAFT-SUITE-API-CONNECTOR-CONTENT-R003`, `SCION-CONNECTOR-CONTROL-R022`, `MEDULLA-TYPED-PACKS-R105`. | `tests/test_pack_import_served.py::test_pack_imports_without_orphans_and_class_query_reaches_subclasses` (planned in `test-spec.md`). The receipt holds no ontology warning. The two class queries return the new subclasses. |
