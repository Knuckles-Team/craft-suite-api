# CONN-CRAFT-SUITE-API — Requirements

Governing specification: [spec.md](spec.md).

Each row identifies one connector behavior and its verification target.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-CRAFT-SUITE-API-R001` | **Credential references.** The connector must resolve authorized credential references in `craft_suite_api/auth.py` when the backend client is built, and must never hold a resolved secret in configuration. Caller chain: `register_backend_tools` in `craft_suite_api/mcp/__init__.py` calls `build_client` in `craft_suite_api/auth.py`, which calls `_auth` to turn `CRAFT_SUITE_API_TOKEN_REF` into SDK header auth on the `session` header, or SDK delegated auth when delegation is enabled. Shape: `build_client` registers the TLS profile and token-client cleanups on one `ExitStack`, and `close_client` closes that stack. | `tests/test_auth.py::test_client_resolves_reference_and_cleans_up` must observe the resolved `session` header, a redacted auth repr and the cleanup on close. |
| `CONN-CRAFT-SUITE-API-R002` | **Bounded API requests.** The connector must enforce origin, TLS, timeout, redirect and response-size limits on every backend request. Caller chain: a backend tool sends through the client from `build_client` in `craft_suite_api/auth.py`, which `_check_origin` validates, the SDK `create_async_http_client` governs, and the `bound_response` hook bounds. Shape: one attempt, `follow_redirects=False`, `TIMEOUT_S` of 30 s and `MAX_BYTES` of 16 MiB, enforced on both the declared length and the streamed body by `_BoundedStream`. | `tests/test_api_wrapper.py::test_oversized_response_rejected`, `::test_redirect_not_followed`, `::test_response_deadline_enforced` and `::test_invalid_provider_origin_rejected` must exercise oversized responses, redirects, deadlines and rejected origins through the real client. |
| `CONN-CRAFT-SUITE-API-R003` | **MCP registration.** The connector must register its backend tools through `craft_suite_api/mcp_server.py` and `craft_suite_api/mcp/__init__.py`. Caller chain: the `scion_sdk.connector` entry point calls `get_mcp_instance` in `craft_suite_api/mcp_server.py`, which calls the SDK `build_server`, which calls `register_backend_tools` in `craft_suite_api/mcp/__init__.py`, which mounts `build_backend_server` from `craft_suite_api/backend.py` under the `craft_suite` namespace. Shape: one registrar and one mounted sub-server, and no request to the backend at build time. | `tests/test_artcraft_mcp_validation.py::test_mcp_instance_registration` must construct the production server without vendor requests and list one `craft_suite_` tool per backend operation plus the registry tools. |
| `CONN-CRAFT-SUITE-API-R004` | **Native content contracts.** The connector must publish packaged prompts, skills, ontology, and its manifest through `craft_suite_api/mcp_server.py`. Caller chain: the SDK `build_server` called from `get_mcp_instance` in `craft_suite_api/mcp_server.py` serves the packaged `skills/`, `ontology/` and `prompts/` directories with no content argument. Shape: the content is declared by the `scion_sdk.connector` and `scion_sdk.prompt_providers` entry points in `pyproject.toml`, and no connector code lists it. | `tests/test_default_content_surfaces.py::test_default_content_surfaces` and `tests/test_source_contract.py::test_served_prompts_match_admitted_capabilities` must list the packaged skills, ontology and prompts through the production server. |
| `CONN-CRAFT-SUITE-API-R005` | **Withhold unscoped ingestion.** The connector must not expose generic ingestion before a tenant/source-scoped ArtCraft mapping and complete receipt contract exist. Caller chain: no tool or entry point reaches an ingestion path, because `craft_suite_api.kg_ingest` and `craft_suite_api.api` are absent from the package. Shape: the test asserts both module specs are missing with `importlib.util.find_spec`. | `tests/test_source_contract.py::test_unscoped_ingestion_is_unavailable` must reject import of the removed ingestion starter. |
| `CONN-CRAFT-SUITE-API-R006` | **Destructive-write confirmation.** Each backend write tool must accept an optional `confirm` argument that is never sent upstream, and a write that is not confirmed must return the SDK refusal as a clean result instead of an error. Caller chain: an MCP client calls a write tool, and `BackendGovernance.on_call_tool` in `craft_suite_api/backend.py` calls `_write`, which calls the SDK `ctx_confirm_destructive` before the request is sent. Shape: `on_call_tool` pops `confirm`, `_write` passes it as `explicit_confirm` and returns `confirmation_refusal` with the write class when unconfirmed, and `_component` adds `confirm` to every write schema and widens every output schema to admit the refusal. | `tests/test_destructive_confirmation_transports.py::test_stdio_no_auth_destructive_call`, `::test_http_no_auth_localhost_destructive_call` and `::test_http_jwt_destructive_call` must show that a client without elicitation is refused with no upstream write until `confirm=true`, and that an eliciting client is asked and then writes. |
| `CONN-CRAFT-SUITE-API-R007` | **Every backend operation as one typed tool.** The connector must serve every operation of the pinned backend API description as its own tool named `craft_suite_<operation id>`, with a typed input schema, an output schema and annotations that mark reads read-only. The backend publishes no MCP server, so the tools are generated from its description with the framework's OpenAPI provider, not written by hand. Caller chain: `build_backend_server` in `craft_suite_api/backend.py` → `backend_document` (`craft_suite_api/backend_catalog.py`) → `served_document` in `craft_suite_api/backend_spec.py`, which checks the sha256 pinned in `craft_suite_api/api_spec/backend.source.json` against the shipped `api_spec/backend.openapi.json` and repairs the description in memory through `normalize` (missing references, untyped parameters, multipart upload bodies, base64 file parts, the `session` credential scheme, the governance class of each operation; a bogus `request` path parameter beside a JSON body is dropped rather than turned into an upload form, and `enum` is dropped from schemas only responses use, because the live backend answers values the description does not list). The provider receives it with `tool_names`, which shortens ids too long for the 64-character MCP limit with a hash suffix. Shape: the served description is produced at point of use; nothing generated is committed and no regenerate step or freshness gate exists. | `tests/test_backend_tools.py::test_every_operation_is_one_typed_tool` must list at least `operation_count()` tools (268 or more) with unique names of 64 characters or fewer, a typed schema for every property, an output schema, and a `confirm` input on writes only; `::test_served_document_is_built_from_the_pinned_source` must find no committed generated description and a shipped document matching its pin; `::test_repairs_keep_json_bodies_and_open_response_enums` must find flux schnell's JSON body intact and no enum on the image-model listing's response. |
| `CONN-CRAFT-SUITE-API-R008` | **Governed writes: typed refusals and audit.** Every backend call must be refused with a typed result while the backend is not configured. Every write (the `generation`, `upload`, `account`, `moderation` and `write` classes) must need the operator switch `CRAFT_SUITE_API_ALLOW_WRITES` as well as a confirmation, and every write decision must be logged to the `craft_suite_api.audit` logger. Caller chain: `BackendGovernance.on_call_tool` in `craft_suite_api/backend.py` resolves the operation through `operation_id`, refuses with `BACKEND_NOT_CONFIGURED` or `WRITES_DISABLED` through `_refusal`, logs `refused`, `unconfirmed` or `sent` with the tool and write class, and `_decode_files` turns base64 upload parts into binary multipart parts. Shape: a refusal is `{cancelled, operation, reason, write_class}`, and no request leaves before the decision. | `tests/test_backend_tools.py::test_unconfigured_backend_refuses_typed`, `::test_writes_disabled_refuse_typed_and_audit`, `::test_unconfirmed_write_is_refused_then_confirm_sends` and `::test_upload_sends_the_decoded_file_as_a_binary_part` must show typed refusals for generation, upload and account writes, audit records, no request before confirmation, and the decoded file bytes in the multipart request. |
| `CONN-CRAFT-SUITE-API-R009` | **Hot-path proof.** A read tool call must reach the exact backend route with the session credential and return the backend's structured result unchanged in under one second, excluding the backend's own latency. Caller chain: an MCP client calls `craft_suite_list_tags_handler`, `BackendGovernance.on_call_tool` passes the read through, and the provider sends it on the client from `build_client`. Shape: no confirmation, no audit and no extra request on a read. | `tests/test_backend_tools.py::test_hot_path_read_reaches_the_exact_route_with_the_session` must observe one request to `/v1/tags/list` with the `session` header and a structured result equal to the response, in under one second. |
